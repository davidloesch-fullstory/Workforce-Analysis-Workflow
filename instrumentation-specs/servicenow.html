What this document is. A pre-flight configuration plan. It tells a FullStory admin exactly which pages, named elements, defined events, and custom properties to set up for a target tool before a workforce automation analysis runs. Configuring these promotes the tool's signal from low-precision URL-path inference to high-precision, action-level events — so the analysis measures real workflows instead of guessing from navigation.

1Surfaces & The Discipline They Force

ServiceNow renders the same Incident table through multiple UIs, each with its own configurable form views. A "category dropdown" is a different DOM node in Service Operations Workspace than in classic UI16, so named elements must be scoped per surface.

SurfaceWhat lives hereNotes for instrumentation
Service Operations Workspace (SOW)Agent home, list view, incident record (e.g. the "SOW - Incident - Overview" view), contextual side panel / Agent AssistModern workspace UI; component-based DOM. Form layout edited via record Additional Actions > Configure > Form Designer.
Classic UI16Standard list & form views of the Incident table, related lists, UI actionsStable form/list structure; many orgs still fulfill here. Different selectors than SOW.
CSM Workspace (if used)Case management equivalent of SOWSame modeling approach; out of scope for this ITSM example.
Why conceptual depth is the right call here. FullStory named elements bind to CSS selectors. SOW's component-driven DOM can produce volatile selectors, so this spec names the action and its surface and leaves selector binding to the admin in-instance (using Inspect Mode on a real session). Confirm each element on both SOW and UI16 if agents use both. Source: FullStory — naming elements applies to CSS selectors only · SN Community — SOW Incident form views Verified vs docs

6How to Configure in FullStory

The admin handoff. All of this is no-code via Data Studio (Data Management). Order matters: pages → elements → events that reference them.

1Define Pages Verified vs docs
Go to Settings > Data Management > Pages → Create Page. Add each page from Section 2 using URL rules (*, **, []). Paste a real instance URL into the search box first to check for conflicts (rules are mutually exclusive).
Source: FullStory — Pages
2Name Elements Verified vs docs
Open a recorded ServiceNow agent session → Page Insights > Inspect Mode → click the control (e.g. Category selector) → name it in Data Studio. Repeat per surface (SOW vs UI16) where agents work in both. The name maps to a CSS selector (element_definition_id).
Source: FullStory — Data Studio · Element Definitions
3Define Events Verified vs docs
In Settings > Data Management > Events → Create Event (or "Define event" from Inspect Mode / the event builder). Compose each event from Section 4 by referencing the named element plus page scope — e.g. clicked element "Resolve button" when Visited URL matches "Incident — Record". Attach the Section 5 properties.
Source: FullStory — Define Events
Then let it capture. Allow ~2–4 weeks of data accumulation before the analysis so volumes are meaningful. After that, the workforce analysis discovers these by name (discover_org_context) and builds metrics directly on them — promoting them from "enrichment" to primary signal, which is exactly what eliminates URL-tokenization guesswork.

How the rollup is used. Start the analysis with the spec'd tool (ServiceNow) for high-precision signal; the "future tool spec" rows tell you where URL-path fallback is still the only signal, so findings there are treated as directional until those tools are instrumented. Each future tool would get its own tab (same structure as the ServiceNow tab) in a later pass.

Dedup & double-count guardrails

  • One workflow = one canonical event source. Where two tools touch the same workflow (e.g. ServiceNow + Jira on escalation), the rollup names the canonical owner to avoid summing both.
  • Cross-tool handoffs (incident → Jira issue) are modeled as a single "linkage" event, not two independent creations.
  • Active-time per tool stays a directional floor, never summed across overlapping tabs.
