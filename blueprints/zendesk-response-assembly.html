What Sessions Revealed

Across 3 observed agent sessions (~7.5 hours, ~37 tickets):

  • Agents spend ~42% of active time composing replies.
  • Dominant pattern: open ticket → read history → copy fragments from previous messages and comment log → paste into composer → edit and stitch → send.
  • One agent copied from history 5+ times to assemble a single response.
  • One agent spent 9 minutes reading + copy-pasting on a single ticket.
  • Knowledge Base accounts for only 0.4% of page views (126 / 34,455) — agents copy from past ticket history instead of consulting KB.
Watch It Happen
▶ 04:12 Agent copies three fragments from the comment log into the reply composer ▶ 09:48 9-minute single-ticket assembly: read history, copy, paste, edit, send
The Human Cost: ~255 hours/month assembling responses by hand; inconsistent quality (depends which old ticket the agent finds); slower resolution; steep ramp for new agents with no history to copy; tribal knowledge trapped in old threads instead of a searchable KB.

Data Flow

  1. Trigger: customer creates or updates a ticket (new comment).
  2. Webhook fires: Zendesk sends ticket ID + event type to middleware.
  3. Context assembly: middleware fetches the full thread, requester info, org metadata, KB articles, and similar resolved tickets.
  4. AI generation: the LLM drafts a response from the assembled context.
  5. Draft delivery: the draft is posted as an internal note on the ticket.
  6. Agent review: the agent opens the ticket, sees the draft, edits, and sends.

Build vs. Buy

ApproachProsCons
Zendesk AI Agent (native)Zero middleware, built-in, Zendesk-managedLess prompt control, Zendesk pricing, limited context control
Custom middlewareFull prompt control, any LLM, custom KB integration, audit trailRequires hosting, more setup, you maintain it
Third-party (Forethought, Ada, …)Turnkey, pre-built Zendesk integrationVendor lock-in, monthly cost, less quality control
Recommendation: Start with custom middleware for maximum control over response quality. Re-evaluate Zendesk AI Agent if its prompt customization improves.

3Detailed Build Steps

Prerequisites

  • Zendesk Admin access (webhooks, API tokens, macros)
  • Cloud hosting account (GCP Cloud Functions, AWS Lambda, or similar)
  • LLM API key (OpenAI, Anthropic, or Google AI)
  • Zendesk API token (Admin Center → Apps and Integrations → Zendesk API)
1Create Zendesk API TokenVerified
  1. Go to Admin Center → Apps and Integrations → Zendesk API.
  2. Enable Token Access and click Add API Token; name it ai-response-drafter.
  3. Copy and store the token securely (used by the middleware).

Auth format for API calls: {email}/token:{api_token}

Source: Zendesk API — Security and Auth
2Build the Middleware Function

Create a serverless function (example: Google Cloud Function, Node.js):

ai-response-drafter/
├── index.js      # Main handler
├── zendesk.js    # Zendesk API client
├── llm.js        # LLM API client
├── prompt.js     # Prompt template builder
├── package.json  # Dependencies
└── .env          # API keys (use Secret Manager in production)

Core logic (pseudocode):

async function handleWebhook(request) {
  const { ticket_id } = request.body;
  const ticket    = await zendesk.getTicket(ticket_id);
  const comments  = await zendesk.getTicketComments(ticket_id);
  const requester = await zendesk.getUser(ticket.requester_id);
  const kb        = await zendesk.searchKB(ticket.subject);
  const similar   = await zendesk.searchTickets(ticket.subject, { status: 'solved', limit: 3 });
  const prompt    = buildPrompt({ ticket, comments, requester, kb, similar });
  const draft     = await llm.generateResponse(prompt);
  await zendesk.addInternalNote(ticket_id, formatDraft(draft));
  return { status: 'ok', ticket_id };
}
3Zendesk API Calls for Context + Draft DeliveryVerified
  • Get ticket + comments: GET /api/v2/tickets/{id}.json, GET /api/v2/tickets/{id}/comments.json
  • Search KB: GET /api/v2/help_center/articles/search.json?query={keywords}
  • Search similar solved tickets: GET /api/v2/search.json?query=type:ticket status:solved {keywords}
  • Post internal note (the AI draft): PUT /api/v2/tickets/{id}.json with ticket.comment.public = false

5Create the Zendesk Webhook + TriggerVerified

Webhook (Admin Center → Apps and Integrations → Webhooks → Create): POST, JSON, endpoint https://{cloud-function-url}/draft, Bearer-token auth.

Trigger (Admin Center → Objects and Rules → Business Rules → Triggers):

  • Conditions (ALL): status is not Solved; comment is present from end user; tags do not contain ai_draft_skip.
  • Action: Notify webhook → AI Response Drafter with body {"ticket_id":"{{ticket.id}}","event":"customer_comment"}.
Source: Zendesk — Creating webhooks · Creating triggers
6Create Agent Macros
  • Use AI Draft — copy the latest internal note (AI draft) into the public reply field.
  • Skip AI Draft — add tag ai_draft_skip (manual compose for sensitive topics).
  • Submit as Pending + 5-Day Follow-up — bundles status + follow-up timer, replacing the 5-click field ritual (pairs with disposition auto-population).

5Validation & Rollout

Testing Checklist

  • Webhook fires on new customer comment (verify in webhook logs)
  • Middleware fetches correct ticket data; KB + similar-ticket search return useful results
  • LLM generates appropriate, on-brand responses
  • Draft appears as internal note on the correct ticket; NOT on solved tickets or agent-only comments
  • Error handling: invalid ticket ID, API timeout, LLM error
  • Rate limiting under burst load (10+ tickets/min)
  • AI draft is clearly marked as AI-generated

Phased Rollout

Week 1–2
Shadow mode, 2 pilot agents, optional use
Week 3–4
Full team, optional; refine prompt from edits
Week 5+
Default starting point; agents keep full control
Rollback: Immediate — disable the Zendesk trigger. Graceful — catch-all trigger tags new tickets ai_draft_skip (drafts stop, no data lost). Full — delete webhook + trigger; agents return to manual workflow with zero impact.
