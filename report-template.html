How This Analysis Works

A transparent methodology you can verify, challenge, and trust.

Estimate Impact

We calculate hours saved using conservative assumptions. Every number traces back to a specific metric and formula you can verify.

The Estimation Formula

Hours Saved / Month  =  Events × Minutes × Eliminability% ÷ 60
Events/Month
How often this workflow happens (from FullStory metrics)
Minutes/Event
How long it takes each time (from session observation)
Eliminability %
What share automation can realistically handle
÷ 60
Convert minutes to hours

Where the Numbers Come From

Every input to the formula has a verifiable source.

Input Source How to Verify
Event Volume FullStory metric query (linked in each candidate's audit trail) Click the metric link → confirm the count matches in FullStory
Time per Event Session replay observation or conservative default from rubric Watch the linked session replay at the cited timestamp → time the action yourself
Eliminability % Based on automation type + workflow characteristics See rationale in each candidate's "How We Got Here" audit trail

Conservative by Design

These estimates are designed to be a floor, not a ceiling. We use conservative defaults, round down when uncertain, and apply modest eliminability percentages. The goal is an estimate a skeptic would accept. Actual results from implementation often exceed these projections.

How to Challenge a Number

If any estimate seems off, here's how to verify it yourself.

  1. Find the candidate card for the opportunity in question (in the team tab)
  2. Expand "How We Got Here" to see the full audit trail
  3. Check the metric link — click it to open the metric in FullStory and confirm the count
  4. Check the session replay — watch the cited timestamp and time the action yourself
  5. Check the formula — verify that Events × Minutes × Eliminability% ÷ 60 = the stated hours
  6. If any input is wrong, recalculate with the corrected value — the formula is transparent

Dashboard Setup Guide

How to Save These Metrics in FullStory

Each metric link above opens the FullStory metric editor pre-loaded with the query used in this analysis. To save for dashboarding:

  1. Click the FullStory Link in the table above
  2. In the metric editor, click "Save"
  3. Name it using the Suggested Dashboard Name from the table (e.g., [WFA-Acme-2026-05] Copied Comment Log)
  4. Navigate to Dashboards → Create New Dashboard
  5. Add each saved metric as a widget
  6. Set the date range to match your implementation timeline
How to Run Post-Implementation Measurement

After implementing one or more automation opportunities:

  1. Return to the agent that produced this analysis
  2. Say: "Run the proof report for {prefix}"
  3. Provide the implementation date and which opportunities were implemented
  4. The agent will re-compute all metrics, compare before/after, pull fresh session replays, and generate a proof report HTML

Alternatively, manually re-run each metric in FullStory with a post-implementation date range and record values in the Before/After table above.

Note on Team Groupings: Team groupings in this analysis are inferred from tool usage patterns because no team/department/role user properties were available in FullStory. Configuring user properties (department, role, team) in FullStory will enable more precise team segmentation in future analyses.
